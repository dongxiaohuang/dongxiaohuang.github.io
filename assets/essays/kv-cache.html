图解 KV Cache

打开任何一家大模型 API 的价格页，你都会看到两个现象：输出的价格是输入的 3–5 倍；同样是输入，命中缓存的比没命中的便宜 10–50 倍。这篇文章要把这两件事讲清楚。

线索只有一个：自注意力里的 K 和 V。把它们存下来，就叫 KV Cache。我们沿用《图解 Transformer》的做法：先从外部把模型看成一个“输入 token → 输出 token”的接口，再一层一层拆开内部结构，把向量放进图里，最后回到账单。

如果你还没读过《图解 Transformer》，建议先读一遍。不过没关系，后面会把我们需要的部分重讲一遍。

价格页上，输出比输入贵好几倍

让我们先从外部看模型：你给它一段提示词（输入），它返回一段回答（输出）。API 按 token 计费，输入和输出分开算。

输入和输出分开计价：输出每个 token 的价格是输入的几倍。

下面是三家官方价格页上几个主力模型的价格（每百万 token，2026-11-24 截取）。每一行左边是三个价格，右边是两个比值。

每一行是一个模型。左：输入（未命中）、缓存命中、输出的美元价；右：输出是输入的几倍，缓存命中比未命中便宜几倍。

这就是两个现象：输出价是输入价的 3–5 倍；缓存命中的输入，比没命中的便宜 10–50 倍。我们一个一个来解释，先看看模型内部。

打开模型，里面是一叠解码器

Prefill 和 Decode 用的是同一叠解码器

和《图解 Transformer》里的原版不同，今天的大模型（GPT、Claude、DeepSeek 这一类）只保留解码器，叫 decoder-only。拆开模型内部，是一叠结构相同的解码器层。

整个模型 → 一叠解码器 → 每个解码器有两个子层。层数没有魔法，不同模型不一样。

每个解码器分成两个子层。输入先流过自注意力层——这一层让模型在处理某个词时，去看看其他词；自注意力的输出再送进一个前馈网络。解码器里的自注意力是带遮罩的：每个词只能看自己和它左边的词，不能偷看右边。

一次请求分成两个阶段。Prefill（预填充）：把你的整段提示词一次读完。Decode（解码）：然后一个 token 一个 token 地往外写。账单上的两个现象，就藏在这两个阶段的差别里。

Prefill 不是 encoder。 原版 Transformer 有 encoder 和 decoder 两部分（以翻译为例：encoder 把原文读完，decoder 再一个词一个词写出译文）。今天的 GPT、Claude、DeepSeek 这类模型只有 decoder，没有 encoder。Prefill 和 Decode 用的是同一叠解码器、同一套权重，只是两种运行方式：Prefill 把提示词里的所有词一次性并行送进去（带遮罩，每个词只看左边），顺便把每个词的 K、V 存下来，再产出第一个输出词；Decode 每次只送进1 个新词。所以它们是推理时的两个阶段，不是两个模块。

同一个 Decoder 的两种用法。Prefill：n 个词一次并行进入，所有词的 K、V 一次性写进 KV Cache，并产出第一个输出词；Decode：每次只进 1 个新词，读缓存，再追加自己的 K、V。上面的图会自动播放：先演示 Prefill，再接着演示 Decode。

Prefill 的产物是什么？ 以提示词 I love eating 为例，Prefill 做完之后，留下两样东西：

  1. KV Cache：这 3 个词在每一层的 K 和 V。它们留在显存里，后面 Decode 的每一步都要读。这是主要产物。
  2. 第一个输出词：模型在最后一个词 eating 的位置，算出“下一个词是什么”的概率（比如 fresh 0.62），从中选一个，就是第一个输出词。前两个位置其实也算出了预测，但提示词里它们的下一个词本来就是已知的（I 后面就是 love），所以用不上。

其他的都扔掉：每个词在各层里产生的中间结果，包括 Q。可以这样理解：K 和 V 是要留着以后查的“笔记”，Q 和中间结果是“草稿纸”，用完就扔。

这带来两个直接的后果：提示词越长，Prefill 要处理的词越多，用户等第一个字出来的时间越长，同时留下的“笔记”也越多，KV Cache 越大。前缀缓存省钱，也是同一个道理：上次做好的“笔记”还在，这次提示词开头一样，就直接用，不用从头再做一遍 Prefill。

每个词先变成一个向量

现在看看向量是怎么在这些组件之间流动的。和所有 NLP 模型一样，我们先把每个词变成一个向量（嵌入）。

每个词变成一个向量。这里画成 4 个格子，真实模型是几千维。

每个位置的词，沿着自己的路径流过解码器。注意这里的一个关键性质：路径之间只在自注意力层有依赖。前馈网络对每个位置独立地使用同一个网络，所以各条路径可以并行。

自注意力是各条路径交换信息的地方；前馈网络各走各的。

这就是 Prefill 快的原因：提示词里所有词的路径，可以一起算。后面我们会回到这一点。

Q、K、V 是同一个向量乘出来的

计算自注意力的第一步，是从每个词的向量里造出三个向量：Query、Key 和 Value。它们由嵌入向量分别乘以三个训练好的矩阵得到。

x 乘上三个训练好的矩阵 W 得到 q、k、v。k、v 留进缓存，q 用完就丢。

这三个矩阵 W 从哪来？ WQ、WK、WV 是模型的权重，训练时学出来，训练完就固定了；推理时每个词都用同一套（每一层、每个头各有自己的一套）。公式很简单：q=xWQ，k=xWK，v=xWV，其中 x 是这个词在这一层的输入向量（第一层是 embedding，之后是上一层的输出）。因为是同一套 W，Prefill 才能把所有词一次性乘进去。同一个词在同一层的 x 和 W 都不会变，它算出的 k、v 就永远一样，这正是 K、V 可以缓存的原因。

它们是什么？是为了计算和理解注意力而造出来的抽象。用图书馆来比喻：Q 是你手里的借书小纸条（我现在想找什么），K 是书架上的分类标签，V 是书本身。

第二步是打分：拿当前词的 q，分别和每个词的 k 做点积。第三步是除以 d 再做 softmax，把分数变成加起来等于 1 的权重。第四步是用权重去乘各个词的 v。第五步是把它们加起来，得到当前词的输出 z。下面这张图会一步一步演示这五步。

当前词是 “eating”：它的 q 和 “I, love, eating” 的 k 打分，再按权重混合它们的 v。向量里的数字是演示值。

写成一个式子，当前词的输出就是：

z=softmax(qK⊤dk)V

其中 K 和 V 是所有可见词的 k、v 叠成的矩阵，dk 是 k 的维度。

请注意图里 q 和 k、v 的区别：q 只属于当前词，只在这一步用；k 和 v 属于每一个词，而且之后的每一步还会再用到它们。 把这句话记住，KV Cache 的全部秘密就在里面。

下一个词是从 z 里挑出来的

我们算出了 z，可是模型最终要吐出的是一个词，z 到词中间还差几步。（这一节是通用原理，视频里没讲。）

从 z 到下一个词：多层之后得到向量 h，乘上词表矩阵得到每个词的分数，softmax 变成概率，再选出一个词。

  1. 多个头的 z 拼起来，乘一个矩阵，再加上这一层的输入（残差连接）。
  2. 过前馈网络，同样加上残差。这一层就算完了。
  3. 重复 N 层。 上一层的输出是下一层的输入。最后一层给每个位置输出一个向量 h，长度和 embedding 一样。
  4. h 乘上“词表矩阵”（LM head），得到词表里每个词一个分数，叫 logits：s=hWvocab。词表通常有几万到十几万个词。
  5. softmax：把分数变成加起来等于 1 的概率：pi=esi∑jesj。
  6. 选词：直接选概率最大的，或者用 Temperature、Top-P 在概率高的几个词里抽样。
  7. 选出的是词表里的编号，再转回文字，就是你看到的下一个字。

生成下一个词时，只用到最后一个位置的 h，其他位置的 h 这一步用不上。这也是为什么 Prefill 只用最后一个输入词的结果来出第一个输出词。

z 是这个词的 embedding 吗？不是。 embedding 是按词编号查表得到的向量，只和这个词本身有关，eating 的 embedding 永远是同一个；z 是这个词看过上下文之后的向量，里面混进了前面词的 V，所以前面是 I love 还是别的词，它的 z 都会不同。还有一点容易混：位置 eating 最后算出的向量，预测的是它后面的词（fresh），不是在描述 eating 本身。

上面的注意力图为了好懂，只画了一个头，也省略了残差和前馈。真实模型里，z 要经过这些步骤才变成这一层的输出。

不缓存的话，每一步都在重算

解码一次只能写出一个词

Prefill 结束后，模型得到第一个输出词。接下来进入 Decode：把这个新词接到末尾，再跑一遍，得到下一个词；再接上，再跑……直到输出结束符。

没有缓存：每一步都把前面所有词的 K、V 重新算一遍。橙色是 K，蓝色是 V。

仔细看每一行里的 K、V 小格子。第 2 行要重新算 “I, love, eating” 的 K 和 V，第 3 行又要重新算一遍——而这些词的 K、V，和上一行算出来的一模一样。因为一个词的 K、V 只取决于它自己和它左边的词，左边没变，结果就不会变。

没有缓存时，生成第 n 个词要重算前面 n 个词的 K、V；一共要算 1+2+…+n≈n2/2 次（这里数的是算 K、V 的次数）。n 到了几千，这就是巨大的浪费。

把算过的 K、V 留下来

办法很朴素：第一次算出某个词的 K、V 之后，把它们存进显存。之后每一步，只需要算新词的 q、k、v；历史词的 K、V 直接从缓存里读。

有缓存：虚线的是从缓存里读的，只有新词的 K、V 需要计算。

现在每一步只新算 1 个词的 K、V。算 K、V 的总量从约 n2/2 降到 n——这是“用空间换时间”。注意缓存省的只是“重复计算 K、V”：注意力打分（新词的 q 和所有历史 K 做点积）每一步仍然要做，一步是 O(n)。

这也回答了一个常见的面试题：为什么只缓存 K 和 V，不缓存 Q？ 因为 Q 只在当前这一步有用，算完就作废，下一步会有新的 Q。K 和 V 是历史，每一步都要翻。

值得存下来的，是这一步算出来、后面每一步还会再用、而且不会再变的东西。

K、V 就属于这种。每个新词都要拿自己的 q 去和所有历史词的 K 打分，再混合所有历史词的 V。历史词的 K、V 只取决于它自己和它左边的词，左边没变，它们就不变。

Q 只属于当前这一步，下一步会有新的 Q，所以不存。注意力分数、权重、输出 z 都由当前词的 q 算出来，q 一变它们就变，所以每一步重算。

缓存里到底存什么？ 存的是每一层、每个历史词的 K 和 V，不存 Q，也不存注意力的“结果”：

东西缓存吗为什么
K缓存每个新词都要拿自己的 q 和所有历史词的 K 打分。K 只取决于那个词自己和它左边的词，之后不会变
V缓存打完分后要用权重混合所有历史词的 V，V 同样不会变
Q不缓存只在当前这一步有用，下一步会有新的 Q
注意力分数和权重不缓存由当前词的 q 和历史的 K 算出来，每来一个新词 q 就变，所以要重算
输出 z不缓存是当前词的 q 的结果。后面的词不直接用旧词的输出，它们读的是旧词在每一层的 K 和 V

旧词的输出会变成下一层里它自己的 K、V，而这些在第一次算那一层时就已经存好了，所以缓存要每一层都存一份。这也是显存占用的来源。

输出贵，是因为解码要一步一步写

现在可以解释第一个现象了。（以下是原理推导，视频和价格页都没有直接这么说。）

Prefill 一次并行；Decode 一步一个词，每一步都要把权重和全部 KV 从显存搬一遍。

Prefill：提示词里的 n 个词一起过模型（还记得前馈网络各路径可以并行吗？），是大块的矩阵乘法，GPU 的算力被吃满。

Decode：每一步只产生 1 个词，必须等上一个词出来才能算下一个。可是每一步，都要把整个模型的权重和整段历史的 KV 从显存搬到计算单元，真正做的计算却很少——瓶颈从“算力”变成了“显存带宽”。

所以输出是“一个一个算”：占用 GPU 的时间更长，也让一张卡同时能服务的请求更少。价格页上输出是输入的 3–5 倍，大致反映了这种差别（具体倍数是各家的定价决策）。

缓存省了重复计算，显存却会涨上去

KV 随上下文和并发一起涨

KV Cache 不是免费的。模型权重的大小是固定的，而 KV 会随着上下文长度和并发用户数一起涨。拖动下面的滑块试试。

示意图：数值不是某个真实模型的，只表达“权重固定，KV 随长度和并发增长”。

估算公式（通用）：

KV 大小≈2×L×Hkv×dhead×n×B×b

其中 2 是 K 和 V 两份，L 是层数，Hkv 是 KV 头数，dhead 是每个头的维度，n 是序列长度，B 是并发数，b 是每个数占的字节数。长文本或多人并发时，KV 占的显存可能远超模型权重本身，一张 80G 的卡很快就会 OOM，这就是常说的“显存墙”。

KV Cache 这么占显存，那上下文是不是就不能很长了？ 不是“不能”，而是“很贵”。KV 的大小和上下文长度成正比，我们算一个具体的例子（以公开的 70B 级模型结构为例：80 层、8 个 KV 头、每头 128 维、16 位存储。这是我按结构自己算的，不是视频里的数字）：每个 token 的 KV 约是 2×80×8×128×2 字节 ≈ 0.31 MB；上下文 128K token，就是约 40 GB，而且这只是一个用户的量。同时服务 10 个用户，光 KV 就要约 400 GB，远远超过一张卡的显存。

上下文长度受限，也不只是因为显存：Prefill 的注意力计算量大约是 O(n2)，随长度的平方增长（每个词都要和左边所有词打分；Prefill 时还没有缓存可用，缓存也省不掉打分），越长首字越慢；模型训练时见过多长的上下文，也决定了它能稳定用多长；太长时模型还容易漏掉中间的信息。所以长上下文模型靠的不是“多放一点”，而是压缩 KV（见下一节）、对 KV 做量化，以及把暂时不用的 KV 挪到 CPU 内存或硬盘。

于是整个行业都在想办法压缩它。vLLM 的 PagedAttention 像操作系统的虚拟内存一样给 KV 分页，减少碎片；更根本的办法，是让 KV 本身变小。

可以把每一份变薄，也可以把好几份并成一份

有两个方向：让每一份 KV 变小，或者让份数变少。

示意图：同一行的宽度代表同样的 128 个 token；每个方块是存下来的一份 KV，越高表示每份越大，越宽表示合并了越多 token。

  • MHA（Multi-Head Attention，传统多头注意力）：每个词、每个头都存一份 K 和 V。
  • MLA（Multi-head Latent Attention，多头潜在注意力，DeepSeek V2/V3）：把 K、V 压进一个低维的 latent 向量，用的时候再展开。压的是每份的厚度，仍然是每个词一份。
  • CSA（Compressed Sparse Attention，压缩稀疏注意力，DeepSeek V4）：每 4 个相邻的词合并成一份；再用一个索引器（可以理解成书的目录）给每份打分，只挑最相关的几份来算。
  • HCA（Heavily Compressed Attention，重度压缩注意力，DeepSeek V4）：每 128 个词合并成一份，只留大意，像课程大纲。CSA 管细节，HCA 管全局，互相兜底。

视频里的数字：V4 Flash 的 KV Cache 只有 V3 的约 7%；V3 在 100 万 token 的上下文下大约需要 84GB 显存，差不多是一张顶配 H100。MLA 到了百万上下文就不够用了——因为它压的是“厚度”，而 100 万个词仍然是 100 万份。（以上数字来自 B 站视频，未对照技术报告。）

开头一样，就可以少算一遍

到目前为止，KV Cache 只在一次请求内部有效：回答一结束，显存里的笔记就被清掉了。可是 Agent 每一轮请求的开头，往往是同一份系统提示词和工具定义。

前缀缓存（Prefix Caching） 把公共前缀的 KV 留在共享缓存池里。下一个请求如果开头一样，就直接读，跳过 Prefill。这就是价格页上“缓存命中的输入”便宜的原因。首字延迟能从几秒降到几十毫秒。

怎么在毫秒内找到能复用的前缀？推理引擎把文本切成固定大小的 token 块（比如每 16 个一块），给每块算哈希，串成一条哈希链，组织成一棵前缀树（radix tree）。100 个用户共用同一份 1 万 token 的系统提示，只存一份主干，每个人的问题是分出去的小枝条。显存紧张时，按 LRU 淘汰最久没人用的分支。

点下排的方块，表示“这一块变了”。从第一个不同的块开始，后面全部未命中（Hit = 命中，Miss = 未命中）。

规则只有一条：必须从第一个 token 开始逐字一致。 开头只要变一个字，哈希链就从根部断了，后面哪怕有一万字完全相同，也全部要重新算。

不变的放前面，会变的放后面

  1. 静态内容放最前，动态内容放最后。 系统提示词、工具定义、固定文档在前；用户提问、时间戳、会话 ID 在后。
  2. 别在提示词开头写时间、用户 ID、状态。 这是最常见的“前缀污染”。
  3. 别在对话中途增删工具。 工具列表变了，前缀就断了。
  4. 看命中情况再优化。 看接口返回里的缓存命中 token 数（DeepSeek 是 prompt_cache_hit_tokens），数字稳定上涨，才说明吃到了缓存。
  5. 不同厂商机制不同。 Claude 需要在请求里加 cache_control（可以只加一个顶层字段，由系统自动管理断点），5 分钟缓存写入是 1.25 倍、1 小时写入是 2 倍输入价，命中读取 0.05–0.1 倍；OpenAI 价格页单列了缓存写入价（以 Sol 为例，30 分钟 1.25 倍，12 小时 2.5 倍）；DeepSeek 自动识别，不用改代码。

自动命中。 不用改代码，后台自动识别并缓存重复前缀。

KV 落盘，不只放显存。 把算好的 KV 转存到分布式 SSD 阵列：从硬盘读比从显存读稍慢，但换来海量容量和极低成本。有三个落盘时机：请求结束时（输入结束和输出结束各打包一个单元，多轮对话的第二轮就能命中第一轮）；公共前缀（不同问题只要共享长文档或系统提示，后台提炼出公共前缀单独存）；固定 token 间隔（超长上下文按固定步长切片）。

把 KV 本身变小。 从 V2/V3 的 MLA，到 V4 的 CSA + HCA（前面那张图）。KV 变小，既降低了显存压力，也降低了存储成本。

结果体现在价格上。 视频里说缓存命中便宜 30 倍，对应当时的价格；2026-11-24 的官方价格页上，V4 Flash 高峰价是 $0.006 对 $0.30，差 50 倍；V4 Pro 是 $0.044 对 $1.32，差 30 倍。一张卡能同时服务的请求更多，也是 V4 敢把默认上下文开到 100 万的底气。

用接龙来理解这件事

  1. AI 写字像玩接龙，一次只能写 1 个字。 读题是一眼全看完（想 1 次），写 6 个字却要想 6 次。想一次，电脑就忙一次，所以写字比读题贵。
  2. 每写一个字，都要回头把前面所有字看一遍。 不然会写得前言不搭后语。可是每次都重读，太累了。
  3. 解决办法：做个笔记本。 读过的重点记下来，下次直接翻笔记，只读新的那一个字。这个笔记本就叫 KV Cache。
  4. 笔记里只记 K 和 V，不记 Q。 想象在图书馆：Q 是你的借书小纸条，借完就扔；K 是书架上的分类标签，V 是书。标签和书，下次还要用，所以留着。
  5. 笔记本会越来越厚，书桌（显存）却只有那么大。 所以要把每页写得更精简（MLA），把相邻几个字合并成一条（CSA、HCA），放不下的搬到大仓库（硬盘）。
  6. 缓存为什么省钱？ 昨天的作业和今天的开头一模一样，就能直接抄笔记。但必须从第一个词开始一模一样：第一个词一变，后面就全部“不认识”，要重新读、重新花钱。所以不变的放前面，会变的（比如时间）放最后。

记住这几件事就够了

  • 输出比输入贵： Decode 一步一个词，每步都要搬权重和 KV，瓶颈是显存带宽；Prefill 可以并行，算力吃满。
  • KV Cache： K、V 属于每个词、之后每一步都要用，所以存起来；Q 只在当前步有用，所以不存。算 K、V 的总量从约 n2/2 降到 n。
  • 代价是显存： KV 随上下文长度和并发数增长，所以要压缩（GQA，Grouped-Query Attention，分组查询注意力；以及上一节的 MLA、CSA、HCA）和分页（PagedAttention，vLLM 提出的 KV 显存分页管理）。
  • 前缀缓存把 KV 跨请求复用，命中规则是从第一个 token 开始逐字一致，所以静态在前、动态在后。
  • DeepSeek： 自动命中 + 硬盘缓存 + 更小的 KV，所以缓存命中价格低到 1/30–1/50。
